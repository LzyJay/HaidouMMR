## 0. 一句话原理

公开做法是用全服几千万场超图分解算隐藏分（外部拿不到）。本方案改为**直接抓每个人的海斗战绩**：用「不含本人」的对局拟合对手实力 θ（团队 Bradley-Terry，Elo 刻度）→ 本人 Elo 轨迹 → **用截图上的分数做整体平移校准**。海斗与峡谷排位是两套独立匹配池，**绝不能用排位段位代理海斗实力**。

## 1. 环境准备

| 依赖 | 版本 / 路径 | 用途 |
|------|------------|------|
| Python | 3.13+ | 全部 `.py` 脚本 |
| Node.js | 18+ | 验证脚本 |
| jsdom | `npm i jsdom` 装到任意目录 | 验证依赖（`NODE_PATH` 指向它） |
| League 客户端 | WeGame 渠道版，需**在线并登录** | 提供 LCU 本地 REST 凭据与战绩数据 |
| 锚点来源 | 一张海斗隐藏分截图 | 提供 `--anchor` 数值（当前 **1541**）与表现分锚点（当前 **64.9**） |

**⚠️ 沙箱说明（2026-09-21 更正，旧「沙箱铁律」已作废）**：
早期版本取 LCU 凭据要走 **PEB + `PROCESS_VM_READ`**，读进程内存会被沙箱拦下，所以当时写了「必须非沙箱运行」。
现在首选路径改成了 `NtQueryInformationProcess(ProcessCommandLineInformation=60)`，**只需要 `PROCESS_QUERY_LIMITED_INFORMATION`**，
因此在**沙箱内也能拿到凭据**，不需要再找非沙箱环境、也不用加 `dangerouslyDisableSandbox`。

唯一仍要客户端**在线并登录**的场景，就是「抓数据」本身（因为要连 `127.0.0.1` 上的客户端）。
**别再照旧说「必须非沙箱」** —— `_lcu_creds2.py` 的 `_cmdline_via_query()` 是首选路径，
它失败才会掉回需要 `VM_READ` 的 PEB 兜底（那条路在受反作弊保护的进程上必然被拒）。

## 4. 关键参数：锚点怎么定

`--anchor` 决定了整条分数平移到哪里，**对齐错了整条分数都错**。

> ⚠️ **本项目有两套彼此独立的锚点，别混**：
> ① **隐藏分锚点**（当前 **1541**）→ 决定所有 mmr / 隐藏分，落在 `02_数据\_desktop_state.json` 的
>    `anchor_score` 与 `_player_elo_build.py` 的 `ANCHOR_DEFAULT`；
> ② **表现分锚点**（当前 **64.9**）→ 只决定「综合评分」落点（`_dash_rebuild.py` 的 `COMPOSITE_ANCHOR`），
>    **完全不影响隐藏分**。两者来自同一张截图的两个不同数字。

1. `--anchor` = 截图里显示的预估隐藏分（当前 **1541**，对应 09-27 18:54 那一局，诺手 11/9/30）。
2. 对齐到哪一局，**首选 `--anchor-game-id <该局 gameId>`**（当前 `10000000005`）：
   - 脚本会自己在新轨迹里找同一局，**重抓多少次都不跑偏**；
   - 桌面版把这个 id 存在 `02_数据\_desktop_state.json`，所以界面上的按钮天然就是对的。
3. `--anchor-games-ago <N>` 只是**回退方案**（找不到那个 gameId 时才用）：
   - ⚠️ 它是相对**Elo 轨迹**数的，而轨迹只包含「对手覆盖率 ≥ 7/9」的局 ——
     **「主人对局数增量」≠「轨迹长度增量」**，拿增量去推会指到错的局上，**分数静默算错**。
   - 真要用它就得**现数**：打开 `02_数据\海斗隐藏分_v2_本次估算.json` 的 `games` 数组（时间正序），
     定位锚点那一局，数它之后还有几局。当前实测值是 **0**（截图就是最新一局拍的；重抓后这个数会变）。
   - 同一个 `hd_data.json`，不同 `--anchor-games-ago` 会给出不同 `estimate`；换锚点必须同步换这个值。

## 6. 换机器复刻要点

1. **Python 3.13+ / Node 18+ 在 PATH 里即可**，本包算法管线零第三方依赖。
2. **jsdom 装到任意目录**：`npm i jsdom`，再把 `NODE_PATH` 指过去（`验证看板.bat` 顶部可改）。
3. **锚点优先用 `--anchor-game-id`**：换机器前把 `02_数据\_desktop_state.json` 一起带走，
   里面存着 `anchor_game_id` / `anchor_score`，脚本按 id 自己定位同一局，**重抓多少次都不跑偏**。
   只能拿到「截图为 1541、之后打了 N 局」这种信息时才退回 `--anchor-games-ago`，
   并且 N 必须**从 `本次估算.json` 的 games 数组现数**（不能拿"总局数增量"推）。
4. **数据文件可整体拷贝继续增量**：把 `hd_data.json` / `player_elo.json` / `player_elo_meta.json` /
   `海斗roster.json` / `my_stats.json` / `_desktop_state.json`（+`.bak`）连同脚本一起带走，
   下次直接 `--seed` 续传，无需从零爬。
5. **展示口径铁律**：看板任何数字都必须是**当前锚点刻度**（现 **1541**）的隐藏分（mmr），
   绝不展示 θ/Elo 内部刻度（`raw_elo` 约 1450~1580，`offset` 现为 −17.1）→ 主人会以为算错。
6. **趋势图禁平滑**：评分趋势折线只画单局实际值，不得叠加滑动均值/均线（主人明确不要）。
7. **两套锚点分开记**：隐藏分锚点（1541）与表现分锚点（64.9）**改一个不用动另一个**；
   但**重锚隐藏分后必须同步三处**：`_desktop_state.json`、`_player_elo_build.py` 的 `ANCHOR_DEFAULT`、
   以及重跑 `_player_elo_build.py` 让 `player_elo_meta.json` 跟上（铁律 45）。
