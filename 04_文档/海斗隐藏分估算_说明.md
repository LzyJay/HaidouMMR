## 三、算法原理

### 3.1 为什么必须用海斗数据
方法前提：匹配系统按 MMR 组队 → "这 10 人被系统安排进同一场"本身携带强弱信息；
而单场**胜负**的判别力只有 0.497(≈随机)。v1 用峡谷段位当代理，等于用另一个游戏的
匹配池来估计这个游戏的隐藏分——主人的质疑完全正确。

### 3.2 两步模型（主信号）
1. **对手实力 θ**：把所有**不含本人**的 3914 场对局扔进团队 Bradley-Terry/Elo 模型，
   多轮迭代拟合每个玩家的海斗能力（Elo 刻度，K 从 26 衰减到 3，每轮向基准收缩防发散）。
   **排除本人的对局**是关键——对手实力完全独立于本人表现，避免循环论证。
2. **本人 Elo 轨迹**：从"对手覆盖率 ≥ 7/9"的连续段起（更早的对手大多已不活跃，θ 缺失会污染），
   按时间顺序做 Elo 更新（K=22），得到逐局轨迹。
3. **锚定**：把截图时(8 局前)的 Elo 对齐到 1928，整体平移 → 当前 ≈ 1957。
   斜率假设 1:1（Elo 1 分 ≈ 外部刻度 1 分），小窗口内是合理近似。

### 3.3 谱分解交叉验证（复刻官方方法）
超图 H(玩家×对局) → Θ = D⁻¹ᐟ²·H·De⁻¹·Hᵀ·D⁻¹ᐟ² → 幂迭代求第二特征向量（须与 φ₁=√deg 正交）。
**结论：局部稀疏网络(中位度=1)谱轴退化，仅 deg≥5 子图有参考价值**——本人在 440 名高频
玩家中分位 52%，与 Elo 模型"匹配圈中位"互相印证。官方那套要在全服 2849 万场才有绝对分位。

## 四、用法

```bash
# 需要: League 客户端登录中(不需要 sona 插件, 不需要 Riot API key)
# 第一步: 抓数据(滚雪球 BFS, 首次 ~9 分钟, 可后台跑)
python _hd_crawl.py --players 300

# 第二步: 估算
python 海斗隐藏分估算_v2.py --anchor 1928 --anchor-games-ago 8
# --anchor        : 截图上的分数
# --anchor-games-ago : 截图之后打了几局(数一下)! 截图前的局才对齐
# 不传 --anchor   : 只输出相对能力(Elo 刻度, 不换算隐藏分)
```

**抓取加速技巧**：`_hd_crawl.py` 已并发 16 线程；第二次跑用 `--seed` 续传。
数据缓存于 `hd_data.json`（3990 局 ≈ 15MB），不必每次重抓——主人打几局后直接跑第二步即可。

**客户端窗口坑**：WeGame 版 `lockfile` 停在 2021 不刷新 → 脚本读 `LeagueClientUx.exe`
进程命令行取 `--app-port`/`--remoting-auth-token`。
~~**必须非沙箱运行**~~ ← **此结论已于 2026-09-22 作废**：现在走 `NtQueryInformationProcess`
（只需 `PROCESS_QUERY_LIMITED_INFORMATION`），**沙箱内也能读**，别再关沙箱。
LCU 列表接口一页只给 ~6-41 局 → 用对手战绩反查本人历史局（或用 SGP 通道一次拿 100 局）。

## 五、局限（请如实看待）

1. **±62 的不确定度**：8 局样本的 Elo 游走误差就是这么大，方向可信、幅度别当真。
2. **匹配圈绝对层级未知**：θ/Elo 只能定位"本人在自己匹配圈内的相对位置"（中位附近），
   圈子的绝对层级靠锚点固定。~~若能再提供一个**新时刻的外部分数**，可校准斜率与漂移。~~
   ⚠️ **2026-09-27 证伪**：主人给的第二批锚点（7 个主页 + 66 个对局详情）**全是固定开黑队友**
   （196 局 100% 同队、0 敌对）→ 同队则胜负同步、Elo 无法区分队内实力 → **这些锚点不能校准斜率**。
3. **斜率 1:1 假设**：外部刻度→分数的插值是非线性的，Elo→外部刻度严格不是 1:1，
   小窗口内近似成立。~~长窗口(>50局)建议用两个锚点做线性回归。~~
   ⚠️ **同上，2026-09-27 证伪**：可获得的锚点都是队友、不具区分度，**做不了线性回归**；
   要验量级必须拿到**敌对**玩家的外部分数。
4. 谱分解在本数据规模上无法给出全服绝对分位（官方要 2849 万场）。
5. 07-08 月的早期对局对手大多已不活跃，θ 缺失 → 这些局**不进** Elo 轨迹（自动跳过）。
