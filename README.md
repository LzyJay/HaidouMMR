## 这是什么

外部「隐藏分」页面只给出一个数字，不公开采集流程和超参数，本地无法直接复现。
这个项目做的事是：**只用你自己的对局网络，离线重建一个可比的分数量表**。

它抓的不是「你的战绩」，而是「**和你同过局的人分别和谁同过局**」——
隐藏分反映的是**你在本服全体玩家里的匹配位次**，而不是你最近 30 场的发挥。
所以这里的核心计算**完全不看胜负**（见下方「算法」第 2 步）。

| 能力 | 说明 |
|---|---|
| 抓取 | 从 LCU / SGP 两条通道拉对局，增量续传，一次最多 100 局 |
| 全量评分 | 给网络里每个出现过的玩家算一个分（谱分解 + 单人 Elo 轨迹） |
| 逐局明细 | 单局 10 人的 9 项指标（伤害/承伤/经济/治疗占比、KDA、参团…） |
| 估算 | 名次 → 分位 → 锚点插值，输出隐藏分 + 置信区间 |
| 看板 | 生成**自包含单文件 HTML**（数据内嵌，双击即开，不联网） |
| 桌面版 | PyInstaller 外壳 + 操作栏，点一下就串完六步流水线 |

## 支持平台

- **Windows**（依赖 WeGame / 腾讯版英雄联盟客户端的本地接口，`lockfile` + `SGP` 端点）
- Python **3.13+**，算法管线**纯标准库、零第三方依赖**
- 桌面版打包额外需要 `pywebview` + `pyinstaller`；断言需要 Node 18+ 与 `jsdom`

## 算法

三步：

```text
① 建超图        每场对局 = 一条同时连 10 人的超边
                关联矩阵 H ∈ {0,1}^(n×m)          ← 只用「谁和谁同过局」
② 谱分解        Θ = D^-1/2 · H · Dₑ^-1 · Hᵀ · D^-1/2
                取第二特征向量 v₂ = 强弱轴         ← 最大特征值对应「玩得多」，去掉
                v₂ 的正负号用 1 bit 胜负信息定向     ← 胜负只干这一件事
③ 名次 → 分数   p = 100·(r-0.5)/N → 分段线性插值 + probit 分位曲线
```

为什么不是「用胜率/KDA 累积推」：在整个样本上跑经典 Elo 迭代，判别能力只有 **0.497**（随机基线 0.5）——
**胜负序列本身几乎不携带可累积的强弱信息**。这也是本项目把「隐藏分」和「对局表现分」拆成两套的原因：

| | 隐藏分（mmr） | 对局表现分（comp） |
|---|---|---|
| 含义 | 全网络刻度上的**长期水平** | **那一局**自身表现换算的分（0~100） |
| 变化 | 跨局基本不变 | 逐局变化 |
| 算法 | 谱分解 + 单人 Elo 轨迹 | `01_脚本/_composite.py` 加权曲线 |
| 依赖胜负 | 只用 1 bit（定方向） | 4% 权重 |

> ⚠️ **可辨识性限制**：尺度在数学上不可辨识（`θ' = aθ + b` 配合斜率 `β/a` 产生完全相同的匹配），
> 所以**只有名次有意义**，「分数」必须靠外部锚点标定。

## 快速开始

### 环境

```bash
git clone https://github.com/LzyJay/HaidouMMR.git
cd HaidouMMR
```

算法管线不需要 `pip install` 任何东西（Python 3.13+ 标准库即可）。
只有打包桌面版和跑断言才需要额外依赖：

```bash
python -m pip install -r 06_桌面版/requirements.txt   # 仅打包 exe 需要
npm i jsdom                                          # 仅跑看板断言需要
```

### 跑一遍完整流水线

先确认**游戏客户端已登录**（抓取时需要；其余步骤离线可跑）：

| # | 命令 | 作用 | 需要客户端 |
|---|---|---|---|
| 1 | `python 01_脚本\_hd_crawl.py --seed` | 抓你自己的对局（增量，遇旧即停） | ✅ |
| 2 | `python 01_脚本\_player_elo_build.py` | 给网络里每个玩家算分 | ❌ |
| 3 | `python 01_脚本\_stats_crawl.py` | 抓逐局 10 人明细与 9 项指标 | ✅ |
| 4 | `python 01_脚本\海斗隐藏分估算_v2.py --auto-anchor` | 估算隐藏分 | ❌ |
| 5 | `python 01_脚本\_dash_rebuild.py` | 重建看板 HTML | ❌ |

第 4 步的锚点：第一次跑没有截图，用 `--auto-anchor` 自动给分（精度一般）；
之后有了外部界面的隐藏分截图，用 `--anchor <分数> --anchor-games-ago <截图后又打了几局>` 精标。

想连对手网络一起扩（更准但慢得多）：

```bash
python 01_脚本\_hd_crawl.py --seed --players 300
```

### 桌面版

```bash
06_桌面版\build.bat
```

会建独立 venv、装依赖、预检、打包，产物落到 `HaidouMMR/`（onedir，启动约 1 秒）。
打包后右键「操作」面板 →「抓新局并重算」，就是上面五步串起来的全自动版本。

### 验证

```bash
01_脚本\验证看板.bat
```

跑 **390+ 条断言**（看板 + 操作栏 + 玩家弹层与视角），全离线，不需要开游戏。

> ⚠️ **看板 HTML 不在本仓库里。** `_dash_rebuild.py` 是「往一份现成 HTML 里注入数据」，
> 前端 JS（渲染、交互、断言依赖的 DOM）都在那份 HTML 里，属于运行期产物。
> 所以 `_verify_dash.js` / `_verify_player.js` 必须配**同版本生成的 HTML** 才能跑通；
> 单独 clone 本仓库是跑不了这两支的。Python 侧（`_dash_rebuild.py` / 测试）不受影响。
>
> 数据契约：`_dash_rebuild.py` 下发的锚点对象键名是 **`anchors`**
> （含 `hidden_anchor` / `composite_anchor` / `composite_formula`）。旧版 HTML 读的是别的键名，
> 用它配新版后端会取不到值 —— 需要把前端那几处读取同步改过来。

## 使用方法

- **看板**：双击 `03_看板\海斗隐藏分_数据看板.html`。单文件、数据内嵌，可以直接发给别人看。
- **改样式**：**不要**直接改 HTML 里的 CSS —— 样式真身是 `06_桌面版\theme.css`，
  改完跑 `python 06_桌面版\apply_theme.py` 注入（`--restore` 可还原，带漂移护栏）。
- **查别人**：看板「逐局战绩 → 明细」里点任意玩家名，能看到 TA 与你的同场记录；
  桌面版下还能现场抓 TA 最近 100 局并估算隐藏分。
- **换数据主人**：看板视角下拉切到谁，就能以 TA 为种子重抓网络；每次成功管线会自动建档
  （`02_数据\_owners\<puuid>\`），之后切换是秒级换档而不是重算。

## 数据与配置

```text
02_数据/
├── hd_data.json               原始对局库（几十 MB，跑第 1 步生成）
├── player_elo.json            全量玩家评分底表（跑第 2 步生成）
├── my_stats.json              本人逐局明细与 9 项指标
├── 海斗roster.json            每局 10 人明细
├── 海斗隐藏分_v2_本次估算.json   估算结果（分数、置信区间、逐局轨迹）
├── 海斗dashboard_data.json    看板数据聚合
├── _desktop_state.json        桌面版运行状态（锚点、上次耗时）
└── _owners/<puuid>/           按数据主人分档的存档
```

`02_数据/` 与 `03_看板/*.html` **都不进版本库**。想备份就整个目录拷走，或者自己另建一个私仓。

## Q&A

<details>
<summary>使用者 Q&A</summary>

#### Q：一定要开游戏才能用吗？

A：只有**抓数据**的两步（第 1、3 步）需要客户端在线并登录。评分、估算、出看板都是纯本地计算，
`02_数据/hd_data.json` 有了之后断网也能跑到结果。

#### Q：会不会被判定为外挂 / 封号？

A：本项目只读**本机客户端自己缓存的本地接口**（`lockfile` 里的端口与 token，以及客户端已经在用的 SGP 端点），
不注入游戏进程、不修改任何客户端文件、不代打、不自动化对局。
但**这与 Riot/腾讯的用户协议处于灰色地带** —— 任何第三方读取客户端数据的行为都由你自己承担风险。
如果你介意，别用。

#### Q：为什么我的分数和外部界面显示的不一样？

A：两套刻度。那边是服务器级全量数据的谱分解 + 它自己的外部锚点；
本项目是**用你的对局网络本地重建**的近似量表，锚点来自你自己的截图。
能比的是**分位/段位**（相对位次），不是绝对分数。差几十上百分是正常的。

#### Q：抓取很慢，能不能加快？

A：瓶颈在**服务端限流**，不在本地。实测 `--players 300` 光拉 300 人的战绩列表就要 500 秒左右（约 0.5 请求/秒），
`--workers 16` 完全帮不上忙。日常只看自己的新局，用 `--seed --players 0` 就够了（秒级）。

</details>

<details>
<summary>开发者 Q&A</summary>

#### Q：改了 `01_脚本/*.py` 要重新打包 exe 吗？

A：**不用**。onedir 产物里 `HaidouMMR/_internal/_scripts/` 是磁盘上的散文件，运行时直接读。
只有改 `06_桌面版/app.py`（被冻进 exe 本体）才必须重新跑 `build.bat`。

#### Q：新增一个要读文件的脚本，路径怎么写？

A：一律从 `01_脚本/_paths.py` 取常量，**不要在脚本里写路径字符串** ——
它同时处理源码模式和 PyInstaller 冻结模式（后者 `__file__` 指向临时解压目录，拿它推包根必错）。

#### Q：为什么断言这么多？

A：这个项目的核心逻辑是数据驱动的（指标按钮只给覆盖率够的指标出、轨迹长度随对局数变），
所以断言守的是**不变量**而不是写死的数字。改动算法参数后，这套断言是唯一能证明「没改坏」的东西。

</details>

## 开发

| 目录 | 职责 |
|---|---|
| `01_脚本/` | 算法管线。`_paths.py` 是路径唯一入口；`_composite.py` 是表现分公式唯一真身 |
| `02_数据/` | 运行期数据（**不进 git**，只有 `.gitkeep`） |
| `03_看板/` | 生成的看板 HTML（**不进 git**，只有 `.gitkeep`） |
| `04_文档/` | 复刻指南 / 估算说明 / SKILL |

- 规模：Python **11,237 行** + JS **1,531 行**，56 个文件
- 根目录 [`00_使用说明.md`](00_使用说明.md) 是**权威手册**：目录清单、数据 schema、**55 条改码铁律**（踩过的坑）
- 改代码前请先读其中的「铁律」一节，尤其是样式注入（单向覆盖）和数据主人切换这两块
- 部分断言依赖 `02_数据/` 里的文件，未跑过抓取时会失败 —— 那是预期行为，不是仓库坏了
